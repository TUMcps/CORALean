# specification/@atomicProposition

CORA methods of `specification/@atomicProposition/` (a class of `specification/` or `specification/signals/`; a single-file class lists its public methods, constructor included), one row each, and where CORALean answers them. Conventions, states and the out-of-scope reasons are in [../README.md](../README.md).

**CORALean counterpart:** `AtomicProposition` (`src/CORALean/Specification/AtomicProposition/`), generic over a family `S : ℕ → Type` of set representations (`ContSet`): the set `set : S k`, the coordinates `dims : Fin k → Fin n` of the ambient space it is a set of (CORA keeps a list of positive integers and does not check its length against `dim(set)`; here the length is the type), and the locations `locs`. `AtomicProposition.Holds` is what the tests are about: a point satisfies the proposition at a location if the location is allowed and its coordinates `dims` lie in the set. The geometric tests are the `Contains` and `IsDisjoint` classes, which are conservative (`true` only if contained, resp. disjoint), so CORA's `'exact'` algorithm and its `'approx'` retry after `CORA:noops` and `CORA:noExactAlg`, and the tolerances (`tol = 1e-12` of `isIntersecting_`, the default of `contains`), are the instance's; the strict `Contains` does not count a set that only lies within the tolerance of the container as contained.
