## Details

**`analyze` — the soundness theorem.** `analyze_sound`: for an analyzer made by the constructor and
a tree of reach sets with proper time intervals (`lo < hi`), every element of the result is a list
of signals that is sound (`SignalsSound`) for one root-to-leaf branch. A signal `True` at `t` says
that every state of every set of the branch whose time interval covers `t` (and that the mask lets
through) satisfies the proposition, `False` that none does. `analyze_complete`: every branch has
such an element. `analyzeTree_sound` and `analyzeTree_complete` are the recursion alone, over any
state. The recursion is bounded by `fuel` for MATLAB's recursion limit (exhausted: `none`).

**`analyze` — the dropped child.** The loop covers `c(1),…,c(end-1)` and the last line `c(1)` again,
so with two or more children the child `c(end)` and everything below it is never analyzed, and the
branch of `c(1)` is in the result twice (`c(end)` was meant). For the reach sets `R(1)` (parent
`0`), `R(2)` and `R(3)` (parent `1`) a literal Python transcription (`copy` as a deep copy, as
`copyElement` copies the builders) with `analyzeSingle` recording the entry it is given returns
`[[1, 2], [1, 2]]`, not `[[1, 2], [1, 3]]`. `priv_modelCheckingSignals` and `verifySTL_seidl` check
the formula on every signal in the result, so a reach set with a fork (hybrid automaton with several
outgoing transitions, split reach sets) is verified on its first branch only, and may be reported
satisfied while a later branch violates the formula (read from the source, not run in MATLAB).

**`analyze` — the Lean statement.** Formalized with every child analyzed
(`ReachSetAnalyzer.analyzeTree`, with `analyzeTree_sound` and `analyzeTree_complete`: each result is
a branch's and each branch has one). The recursion as printed is `ReachSetAnalyzer.analyzeTreeCora`,
and `ReachSetAnalyzer.analyzeTreeCora_counterexample` computes both results on the fork.
