# specification/@syntaxTree

CORA methods of `specification/@syntaxTree/` (a class of `specification/` or `specification/signals/`; a single-file class lists its public methods, constructor included), one row each, and where CORALean answers them. Conventions, states and the out-of-scope reasons are in [../README.md](../README.md).

**CORALean counterpart:** `SyntaxTree` (`src/CORALean/Specification/SyntaxTree/`), CORA's expression tree of the forward-backward contractor: a leaf variable or an operator node holding the interval that encloses its value over the box and the `funHan` that narrows its operand's interval. It is not related to `STL.Expr` (a predicate's expression, evaluated at a point); `eval` is the function a tree denotes and `IsSound` says its intervals and `funHan`s are correct.

## Details

**`power` — the natural exponent.** A natural exponent (`exp = 0` returns `intPrev`; negative and
fractional exponents are not modelled). `power_sound`, `isSound_power`. Array operands (the loop
over entries) are not modelled.

**`power` — the negative odd exponent.** `power` and `mpower` accept any numeric `exp`, and
`interval/power` supports a negative integer one (`(1 ./ base) .^ -exponent`). For `exp < 0` odd,
`x -> x^exp` is decreasing on each side of `0` and sign-preserving, so a target `int` with `0` in
its interior has the two solution rays `x <= nthroot(inf,exp)` and `x >= nthroot(sup,exp)`, and the
printed interval is the gap between them. For `x^(-1) - y = 0` over `[-2,2] x [-1,2]`, the forward
value of `x^(-1)` is `1 ./ [-2,2] = [-Inf,Inf]`, the `minus` node hands the `power` node
`int = [-Inf,Inf] & ([0,0] + [-1,2]) = [-1,2]`, `nthroot(-1,-1) = -1` and `nthroot(2,-1) = 1/2` give
`res = [-1,1/2]`. So `x` is narrowed to `[-1,1/2]`, though `(1,1)` solves the constraint in the box
(read from the source, not run). A Python transcription of the lines agrees, and finds no unsound
case for a nonnegative or a negative even exponent. Not affected: negative even exponents (the
`int < 0` branch throws `CORA:outOfDomain` only where no solution exists).

**`power` — the Lean statement.** Formalized as a statement about the `funHan`, as the real layer
holds no infinite bound for the forward value: `SyntaxTree.funHanPowerOddCora` is the odd branch as
printed, for an integer exponent (`nthroot(0,exp) = Inf` for `exp < 0` is not modelled), with a
counterexample theorem. The formalized `SyntaxTree.power` takes a natural exponent, where the branch
is sound (`power_sound`).

**`sinh` — the cut target.** `sinh` takes every real value, and `aux_sinh_` then applies `asinh` to
the cut target. `backpropagation` hands the node a target inside the node's own interval (every
`funHan` returns `intPrev & ...`), so a target beyond `[-1,1]` is cut and the contraction loses the
solutions where `sinh x` leaves `[-1,1]`. For `sinh(x1) - x2 = 0` over `[0,3] x [0,3/2]`, the target
of the `sinh` node is `[0,3/2]`, cut to `[0,1]`, and `x1` is narrowed to `[0, asinh 1]` with
`asinh 1 < 1`, though `(1, sinh 1)` solves the constraint in the box (read from the source, not
run).

**`sinh` — the Lean nodes.** `sinh` is the node with `aux_sinh_` without that line, whose `funHan`
is sound (`funHanSinh_sound`, `isSound_sinh`). `sinhCora` is the printed one and
`sinhCora_counterexample` the lost zero.

**`tan` — the cut target.** `tan` takes every real value, so a target beyond `[-1,1]` is cut and the
contraction loses the solutions with `tan x > 1`. For `tan(x1) - x2 = 0` over `[0,pi/3] x [0,2]`,
the target of the `tan` node is `[0,sqrt 3]`, cut to `[0,1]`, and the periodic search returns
`[0, pi/4]` for `x1`, though `(pi/3, sqrt 3)` solves the constraint in the box (read from the
source, not run).

**`tan` — the Lean nodes.** `tan` is the node with the line removed (`tan_sound`, `isSound_tan`).
`tanCora` is the printed one and `tanCora_counterexample` the lost zero.
