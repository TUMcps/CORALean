# Reachability Analysis and its Application to the Safety Assessment of Autonomous Cars

M. Althoff. "Reachability Analysis and its Application to the Safety Assessment of
Autonomous Cars". PhD thesis, TU München, 2010.

**Source:** https://mediatum.ub.tum.de/doc/1287517 (mediaTUM record 1287517, served as PDF; read directly with a custom PDF-content-stream text extractor since no PDF rasterizer was available in this environment — poppler/pdftoppm and pypdf are not installed here, and Read's PDF-page mode depends on pdftoppm)  
**Inventory:** confirmed (Chapter 3 read cover-to-cover, pp. 28-86 of the thesis = PDF pages 46-104)

Chapter 3 is where continuous-time reachability in CORALean comes from: the
truncated exponential with a tail bound, the correction matrices that pay for
linear interpolation over a step, and the input solution a step's enclosure is
built on. §3.3 is the uncertain-parameter case, which `LinParamSys` follows at
an interval matrix and a matrix zonotope; §3.5.5 is where `ZonoBundle` comes
from. Files cite it only where no paper we hold states the result
(`scripts/thesis-ref-allowlist.txt`); where one does, the file cites the paper and the row
below points to it.

## Findings

**Prop. 3.1 — the tail.** The printed proof pulls one `[−1,1]` out of two independent remainders, and the bound does not follow; the proposition holds for another reason. [`CorrectionMatrix.lean`](../../src/CORALean/ContDynamics/LinearSys/MatExp/Theorems/CorrectionMatrix.lean), [`ExpDiff.lean`](../../src/CORALean/ContDynamics/LinearSys/MatExp/Theorems/ExpDiff.lean)

**Prop. 3.8 — the intersection.** `Z₁ ∩ Z₂ = Z*` is read off `A + (B ∩ C) = (A + B) ∩ (A + C)`, which is false for sets, convex `A` included. The claim holds; what it needs is that `Z*` is convex. [`SplitIntersection.lean`](../../src/CORALean/ContSet/Zonotope/Real/Theorems/SplitIntersection.lean)

**Lemma 3.1 — the vertex branch.** The statement carries no hypothesis on `t`, and at `t = 0` its `-1/t` branch returns `-1/2` where γ is constantly `0`: sound, but not the exact value claimed. [`QuadTermAttained.lean`](../../src/CORALean/ContDynamics/LinearSys/MatExp/Theorems/QuadTermAttained.lean)

**Thm. 3.2 — `(At)^i`.** The sum's powers carry no association, and interval matrix multiplication is not associative — the same section says so two paragraphs earlier — so the printed formula names a family of enclosures rather than one. [`ExpIntervalTaylorTail.lean`](../../src/CORALean/ContDynamics/LinearSys/MatExp/Operations/ExpIntervalTaylorTail.lean)

**Heuristic 3.1 — the performance measure.** Printed as a product, `ϱ_j = max(l1,j/l̄) · max(l2,j/l̄)` (confirmed against two independent PDF extractions), but the very next sentence needs a sum: "the lowest performance measure is less than 1 ... implies `l1,j ≤ l̄` and `l2,j ≤ l̄`" only follows if both non-negative maxima are *added*, since a product under `1` bounds neither factor (`0.1 · 5 < 1`). Formalized as printed regardless — a heuristic carries no soundness obligation, only a usefulness one, and this repository proves neither. [`SplitRank.lean`](../../src/CORALean/ContSet/Zonotope/Real/Operations/SplitRank.lean)

**Cor. 3.2 — the Hessian range.** The proof has it that `{ξ(z, z*) | z ∈ Ẑ}` "is independent of z*", so that `max |J_i|` is unaffected by the linearization point. That set is the convex hull of `Ẑ` and `z*`, which is `Ẑ` only when `z* ∈ Ẑ` and strictly larger otherwise, so the max is affected. The corollary holds because the dependence runs one way: a bound valid at any `z*` is valid at the center. [`AbstrErrLinCenterSubset.lean`](../../src/CORALean/ContDynamics/NonlinearSys/Theorems/AbstrErrLinCenterSubset.lean)

**Prop. 3.4 — the tail.** The proof is explicitly omitted, resting on `~F = A⁻¹F` and the claim `A⁻¹E = E/‖A‖∞` "since E is computed using the infinity norm" — exactly the inversion the surrounding paragraph says the Taylor-expansion route is meant to avoid, and not a bound that holds of a general `A`. What holds, proved directly from `F̃`'s own series without ever forming `A⁻¹`, is that the tail is `r` times the exponential's own remainder — the scaling integrating the exponential's tail over `[0,r]` gives every finite order too. **Alg. 5 — the loop condition.** The listing loops `while R^H([(k−1)r, kr]) ≠ ∅ or t < t_f`, which keeps iterating up to `t_f` after the set has left the invariant and, once past `t_f`, only stops when it leaves; `t` is never assigned. Fig. 3.20 and the text compute the set "until invariant is left" and stop at `t_f`, which is the condition with "and" and `t = kr`; `Location.reachGuard` reads it so, and `Location.IsTrajectory.reachGuard_outer` proves the listing sound under that reading. The same listing is NAHS'10 `Alg. 1`. [`ReachGuard.lean`](../../src/CORALean/HybridDynamics/Operations/ReachGuard.lean)

**Alg. 4 — the subtracted input solution.** Line 2 reuses Alg. 3's `CH(X₀, e^{Ar}X₀ + P̃(r)) − P̃(r)`, whose purpose, stated when Alg. 3 introduces it, is to subtract the constant's contribution here and add it back later so that the homogeneous set at `kr` stays `e^{Akr}R(0)`. Here `P̃(r) = C(r)ũ` with `C(r) := ∫₀ʳ e^{At}dt` an interval matrix, so it is a box and nothing cancels: read `−` as a Minkowski sum with `−P̃(r)` and the width is paid twice; read it as an erosion and the term can be empty, dropping the homogeneous part altogether.
